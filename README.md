# JARVIS AI

> **"Hey JARVIS" - and it responds. Your personal AI assistant that actually sees, hears, and understands.**

I built JARVIS because I wanted an AI assistant that *just works*. Not one that needs perfect conditions or scripted commands - one that adapts to you, learns from context, and handles the messy reality of everyday computing.

**See it in action**: [jarvis-portfolio.vercel.app](https://jarvis-portfolio-kyko2n4hg-derek-russells-projects-090370ad.vercel.app)

## What Makes JARVIS Different?

**It sees your screen.** JARVIS knows what you're looking at - whether it's a software update notification, an error message, or a document you're working on.

**It understands context.** Screen locked? JARVIS unlocks it before opening Safari. Multiple tabs open? It knows which browser you're using. This isn't rigid automation - it's intelligence.

**It actually works.** From 80-100% CPU usage down to 1-5%. From crashes to 90% automatic recovery. I didn't just build features - I built a system that runs reliably in production, every day.

## The Engineering Story

Building JARVIS meant solving real problems:

**CPU Optimization** → How do you go from a system that maxes out your CPU to one that uses less than your music player?

**ML Routing** → How do you build a classifier that adapts instead of breaking every time someone phrases a command differently?

**Self-Healing** → What happens when a Rust component crashes at 3 AM? It switches to Python automatically, fixes itself, and switches back.

**Context Awareness** → Your screen is locked and you say "open Safari" - should it fail? Or unlock the screen first?

**Computer Vision** → How do you teach an AI to *see* software updates, error messages, and UI changes across any application?

I wrote about all of this. The wins, the failures, the 2 AM debugging sessions. Real engineering, real solutions.
